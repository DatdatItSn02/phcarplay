# Kiến trúc

## Cấu trúc thư mục
```
public/            Thư mục web duy nhất công khai
  index.php        ĐIỂM VÀO DUY NHẤT: điều hướng mọi yêu cầu vào đây. Tự chia: /api/... (API người dùng), /admin/api/... (API quản trị, phiên riêng), /assets/... (file tĩnh), /admin... (trang quản trị), còn lại (trang giao diện người dùng)
  assets/css, js   Giao diện
app/
  Core/            Hạ tầng: Router, Request, Response, Session, Database, Config, Env, Container, Pagination, Sql
  Middleware/      Csrf, RequireUser; quản trị: RequireAdmin, RequirePasswordChanged, RequireMaster
  Controllers/     Nhận Request, gọi Service, trả Response. Không chứa SQL hay nghiệp vụ nặng
  Controllers/Admin/  Controller của API quản trị
  Services/        Nghiệp vụ: AuthService, PasswordResetService, Mailer, PasswordHasher, EntitlementService, LicenseKeyService (key: tạo, thu hồi, nhập); quản trị: AdminAuthService, AdminAccountService, AdminPasswordResetService, AdminUserService, AdminPlaylistService, AdminStatsService, AuditService, AuditViewService; LicensePeriod (tính cộng ngày hạn dùng)
  Repositories/    Chỉ chứa câu SQL (mỗi bảng một lớp)
routes/api.php     Danh sách đường dẫn API người dùng
routes/admin.php   Danh sách đường dẫn API quản trị (/admin/api)
config/            Cấu hình, đọc từ .env
database/schema.sql   Toàn bộ cấu trúc hiện tại, dán vào phpMyAdmin để tạo nhanh (luôn cập nhật cùng migration)
database/migrations/  001_*.sql, 002_*.sql ... chạy bằng bin/migrate.php
bin/               Lệnh dòng lệnh
storage/           Log, thư ghi ra file khi phát triển
tests/             unit/, integration/, js/, support/ (SQLite dùng khi không có MySQL, máy chủ thử serve_sqlite.php; `SqliteTestPdo` đổi `INSERT IGNORE` của MySQL sang `INSERT OR IGNORE` của SQLite chỉ khi thử)
mobile/            Giai đoạn 13: vỏ ứng dụng Android (android/, Java) và iOS (ios/, Swift + XcodeGen) mở website; cấu hình chung config/app.json; hướng dẫn mobile/README.md
.github/workflows/mobile-build.yml   Build thử Android (ra APK) và iOS (kiểm tra biên dịch) trên GitHub Actions
```

## Luồng một yêu cầu API
`public/index.php` (đường dẫn /api/...) -> bắt đầu phiên -> Router (middleware Csrf toàn cục) -> middleware của route (ví dụ RequireUser) -> Controller -> Service -> Repository -> MySQL. Mọi lỗi ném `HttpException` sẽ được `ErrorHandler` đổi thành JSON `{"ok":false,"error":{...}}`.

## Khu vực quản trị (giai đoạn 5)
- **Phiên riêng:** `/admin/api` gọi `Session::start('admin')` (cookie `carweb_admin`, 8 giờ). Đăng nhập người dùng và quản trị không dính nhau.
- **Phân quyền ở máy chủ**, bằng middleware xếp theo nhóm route trong `routes/admin.php`: `RequireAdmin` → `RequirePasswordChanged` → `RequireMaster`. Ẩn nút trên giao diện chỉ là tiện lợi, không phải bảo mật. Quy tắc bảo vệ master nằm trong `AdminAccountService`.
- **Phiên mất hiệu lực khi đổi mật khẩu** nhờ "dấu vân tay" mật khẩu trong phiên (xem `docs/API.md`).
- **Nhật ký thao tác:** mọi thao tác quan trọng gọi `AuditService::record()` (bảng `audit_log`, chỉ thêm, không sửa/xóa). Thêm chức năng quản trị mới thì ghi nhật ký ở Service, không ở Controller.
- **Giao diện:** `public/assets/js/admin/` là một ứng dụng JS riêng (`main.js` là điểm vào), dùng chung `core/` và `app.css`, thêm `admin.css`. `ui.js` có sẵn ô nhập, form, hộp xác nhận, nhãn, ô tìm kiếm có trì hoãn, ô chọn, thanh chuyển trang, sao chép/tải CSV. Hộp thoại dùng chung với ứng dụng người dùng ở `core/dialog.js` (Esc, giữ phím Tab trong hộp, trả focus; hộp mở chồng nhau thì chỉ hộp trên cùng nhận phím). Mỗi mục là `mountXxx(el, ctx)` trả về hàm dọn dẹp; thêm mục mới: viết hàm đó rồi thêm vào mảng `sections` trong `admin/shell.js` (`masterOnly: true` để chỉ master thấy).
- **Danh sách phân trang:** Controller dùng `Pagination::fromQuery()`, Repository có cặp `search()` / `countSearch()` dùng chung một đoạn điều kiện, ô tìm kiếm dùng `Sql::like()` (thoát `%`, `_`). SQL viết sao cho chạy được cả MySQL lẫn SQLite (`LIKE ? ESCAPE '!'`, số trang ghi thẳng vào LIMIT/OFFSET sau khi ép kiểu số nguyên).
- **Key kích hoạt:** `LicenseKeyService` sinh mã bằng `random_bytes`; nhập key chạy trong **một giao dịch** (`LicenseKeyRepository::redeem`): khóa dòng người dùng (hai key nhập cùng lúc không đè hạn của nhau), rồi "chiếm" key bằng cập nhật có điều kiện `status = 'unused'`, nên hai người nhập cùng một key thì chỉ một người thắng. Cách cộng ngày nằm ở `LicensePeriod::extend()` (dùng chung cho nhập key và gia hạn tay).
- **Xóa người dùng** (`UserRepository::deleteWithData`) xóa dây chuyền bằng mã vì database không có khóa ngoại: bài và playlist, cài đặt, token đặt lại mật khẩu, rồi chính người dùng; key đã nhập được giữ lại.

## Quy ước
- Phản hồi thành công: `{"ok":true,"data":...}`. Lỗi: `{"ok":false,"error":{"code","message","details"}}`.
- Controller chỉ lấy dữ liệu vào, kiểm tra, gọi Service. Service giữ nghiệp vụ. Repository giữ SQL (luôn dùng tham số `?`).
- Đối tượng được tạo tự động theo kiểu khai báo ở hàm khởi tạo (`Container`). Chỉ cần `Container::bind()` khi cần cấu hình đặc biệt.
- Mật khẩu: `md5(md5(mật khẩu) . salt)`, toàn bộ nằm trong `Services/PasswordHasher.php`.
- Đăng nhập một thiết bị: `Services/DeviceSessionService.php` (xem `docs/API.md`). Mọi route cần đăng nhập phải bọc trong middleware `RequireUser`, middleware này đã kiểm tra thiết bị.
- Thêm API quản trị: giống API thường nhưng route nằm trong `routes/admin.php`, Controller trong `app/Controllers/Admin/`, và bọc đúng nhóm middleware.
- Quyền dùng tính năng: hỏi `EntitlementService`, không rải điều kiện khắp nơi. Công tắc `ENFORCE_LICENSE` mặc định tắt.
- Ngày giờ lưu theo múi giờ `APP_TIMEZONE`.
- **Database không dùng khóa ngoại (FOREIGN KEY).** Bảng liên kết nhau bằng cột id (ví dụ `password_resets.account_id`, sau này `playlist_items.playlist_id`), có `KEY` (chỉ mục) trên cột liên kết. Việc xóa dây chuyền, kiểm tra tồn tại do Service/Repository xử lý (xóa playlist thì phải tự đánh dấu xóa các bài của nó).
- **Không bao giờ xóa dòng khỏi database (giai đoạn 8).** Không dùng `DELETE`, `TRUNCATE`, `REPLACE INTO` (có kiểm thử chặn). "Xóa" = `UPDATE ... SET deleted_at, deleted_by_type, deleted_by_id, deleted_by_email` qua `Repositories/SoftDelete.php`; mọi truy vấn thường lọc `deleted_at IS NULL`, danh sách quản trị có bộ lọc `deleted=1`. Bảng `users`, `admins` có cột `alive` (1 hoặc NULL) với khóa duy nhất `(email, alive)` để email của tài khoản đã xóa đăng ký lại được. Bài đã bỏ khỏi playlist được thêm lại thì dùng lại dòng cũ. Bảng mới có chức năng xóa phải thêm 4 cột `deleted_*` như vậy.

- `modules/youtube/media.js` gói phần phát media: MỘT thẻ `<video>` dùng suốt phiên, hàng đợi (`queue.js`), động cơ phát HLS/mp4 (`playerEngine.js`), điều phối và chế độ Mix (`playerController.js`, `mix.js`), kho playlist dùng chung cho khách và thành viên (`playlistStore.js`), cùng cửa sổ nổi, toàn màn hình và Media Session (mục dưới). Các panel chỉ dùng `ctx.media`.
- `modules/pip/` (giai đoạn 4, chỉ phía trình duyệt, không có API hay database riêng), đều là JS thuần nhận `video`/`document` từ ngoài vào nên kiểm thử được bằng đối tượng giả (`tests/js/pip.test.mjs`):

Trạng thái `{supported, allowed, active, ready, reason, hint}`. `allowed` lấy từ quyền `pip` của `EntitlementService` (đi qua `session.features`).
  - `fullscreen.js`: toàn màn hình thẻ video; tạm bật `video.controls` khi đang toàn màn hình (thẻ video của app không có thanh điều khiển) và tắt lại khi thoát.
  - `mediaSession.js`: tên bài, kênh, ảnh bìa, các nút phát/dừng/trước/sau/tua trên cửa sổ nổi, thanh thông báo, màn hình khóa.

Video phát trực tiếp từ máy chủ Piped/Invidious về trình duyệt (Invidious: `local=true`). `php bin/video-scan.php` (`Services/VideoSourceScanner.php`) tìm địa chỉ đang phát được.

Tự phát (`autoMix`) chỉ có tác dụng ở chế độ Lần lượt (`off`); lặp hay trộn bài thì nút Tự phát khóa. Âm lượng (bản 12.2): `media.volume` (get/set/toggleMute/onChange) áp cho thẻ video và trình phát YouTube (`embed.setVolume`), nhớ trên thiết bị (`carweb_volume`); thanh âm lượng `.volrow` dưới hàng nút. `playbackPrefs.js` nhớ lựa chọn trên thiết bị (`carweb_playback`) và tài khoản (`/api/user/preferences`, khóa `playback`). Giao diện: nút chế độ phát (`.pill-repeat`) cạnh Tự phát.
- **Bài bạn hay nghe (giai đoạn 11):** bảng `user_play_stats` (migration 009), `Repositories/PlayStatsRepository.php`, `Services/PlayStatsService.php`, `Controllers/PlayStatsController.php` (`/api/user/plays...`). Giao diện: `modules/youtube/playStats.js` (bộ đếm `createPlayCounter` gắn vào `media.surface` timeupdate, đặt lại khi điều phối bắt đầu nạp bài; kho máy chủ cho tài khoản, kho `localStorage` cho khách; `mergeHome` ghép bài hay nghe + bài gợi ý cho đủ 20). `homeView.js` dựng tab "Tất cả" bằng `mergeHome`, cập nhật khi quay lại Trang chủ; `videoRow` hiện dòng "Bạn hay nghe" (không ghi số lần) cho bài hay nghe, kèm `data-frequent`; Cài đặt có "Xóa danh sách hay nghe".

Trong ứng dụng tắt hẳn cửa sổ nổi (`createPip({disabled})`, không phát ở nền). `<html data-app="android|ios">` để CSS phân biệt khi cần. Máy chủ: `DeviceSessionService::describe` ghi "Ứng dụng / Android|iOS".
- Màn hình chính gồm hai khung lấy từ sổ đăng ký panel (`core/panels.js`). Thêm khung mới: viết `{id, title, mount(container, ctx)}`, `registerPanel(...)`, rồi đặt vào `SLOTS` trong `modules/shell/shell.js`.
- Logic chia màn hình nằm ở `core/layoutMath.js` và `core/splitController.js` (thuần JS, có kiểm thử); `modules/layout/splitView.js` chỉ lo phần DOM và kéo thả.
- Không dùng `innerHTML` với dữ liệu người dùng; dùng `h()` trong `core/dom.js`.

## Bảo mật (giai đoạn 7)
- **SQL**: luôn dùng tham số `?`; `LIMIT/OFFSET` chỉ nhận số nguyên đã ép kiểu. **XSS**: giao diện không dùng `innerHTML`; `index.php` chỉ chèn JSON đã mã hóa với `JSON_HEX_TAG`.
- **CSRF**: mọi thao tác ghi cần header `X-CSRF-Token` (middleware `Csrf`); cookie phiên `HttpOnly`, `SameSite=Lax`, `Secure` khi HTTPS.
- **Phiên** (`Core/Session.php`): `use_strict_mode`, đổi ID sau đăng nhập, file phiên riêng ở `storage/sessions/{user,admin}`.
- **Giới hạn tần suất**: `Services/RateLimiter.php` (đếm bằng file trong `storage/cache/ratelimit`, lỗi ghi thì cho qua), dùng ở quên mật khẩu, đăng ký, nhập key và API YouTube. `Services/LoginThrottle.php` (chỉ đếm lần đăng nhập sai theo email+IP, email, IP) **mặc định tắt** vì dự án quyết định không giới hạn số lần đăng nhập sai (`LOGIN_THROTTLE=true` để bật); khi tắt vẫn dùng bộ đếm để giới hạn số dòng nhật ký đăng nhập quản trị sai. Thêm chỗ cần giới hạn: `$limiter->enforce('khoa:' . $request->ip, sốLần, giây, 'Lời nhắn.')`. Lỗi 429 `TOO_MANY_ATTEMPTS` có `details.retry_after` và header `Retry-After`.
- **Tiêu đề bảo mật** (`Core/SecurityHeaders.php`): CSP (script chỉ từ website, đoạn khởi tạo theme theo mã băm sha256, hls.js từ nguồn đã cấu hình), `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS khi HTTPS; API trả `default-src 'none'`. Thêm script nội tuyến mới vào trang thì phải đưa vào tính mã băm, nếu không CSP sẽ chặn.
- **IP người dùng**: `Request::clientIp()` chỉ đọc header proxy khi `CLIENT_IP_HEADER` được đặt.
- **Đặt nhầm thư mục web**: `.htaccess` ở thư mục gốc chuyển mọi yêu cầu vào `public/`; các thư mục nội bộ có `.htaccess` chặn truy cập; mọi lệnh trong `bin/` và `tests/run.php` từ chối chạy qua web.
- **Mật khẩu**: `md5(md5(mật khẩu) . salt)` theo yêu cầu dự án (xem rủi ro trong `docs/DEPLOY.md` mục 8); toàn bộ nằm trong `Services/PasswordHasher.php`.
- `php bin/doctor.php` (`Services/SystemCheck.php`) kiểm tra cấu hình, database, quyền thư mục, Piped và tự gọi website qua `APP_URL` để phát hiện lộ `.env`.

## Triển khai
Hướng dẫn đầy đủ: `docs/DEPLOY.md`.
Chỉ cần máy chủ của bạn chuyển **mọi yêu cầu không phải file có thật** vào `public/index.php` và giữ nguyên `REQUEST_URI`. File này đã tự xử lý `/api`, `/assets` và trang giao diện (kể cả khi máy chủ điều hướng cả yêu cầu file tĩnh vào đây).

**Apache:** document root là `public/`, bật `mod_rewrite` (đã có `public/.htaccess`).

**Nginx:**
```nginx
root /đường/dẫn/carweb/public;
location / { try_files $uri /index.php?$query_string; }
location ~ \.php$ { include fastcgi_params; fastcgi_pass unix:/run/php/php7.4-fpm.sock; fastcgi_param SCRIPT_FILENAME $document_root/index.php; }
```
**Máy chủ riêng:** chạy `public/index.php` cho mọi yêu cầu, đặt biến `REQUEST_URI` là đường dẫn gốc (có cả query string). Nếu website nằm trong thư mục con, đặt `APP_BASE_PATH` trong `.env`.

Không để thư mục `app/`, `config/`, `.env`, `storage/` nằm trong web root (nếu lỡ, `.htaccess` ở thư mục gốc chuyển mọi yêu cầu vào `public/`; chạy `php bin/doctor.php` để kiểm tra).
